# RestoFlow 业务流程文档

## 1. 文档说明

- **目的**：定义各业务对象的状态流转与核心操作步骤，是 database-design.md（状态字段）与 api-design.md（接口动作）的输入
- **范围约定**：本文只描述业务规则与操作路径，不涉及实现方式；本文使用的状态词（已开台、待清台、待制作等）为全项目权威定义
- **与需求的关系**：每个流程步骤标注需求编号（见第 5 章追溯表）；需求变更时同步更新本文并记录 CHANGELOG.md

## 2. 状态机

### 2.1 桌台状态机

```
空闲 ──开台──▶ 占用 ──结账完成──▶ 待清台 ──清台──▶ 空闲
                  ▲                   │
                  └──────反结账───────┘
```

| 当前状态 | 操作 | 目标状态 | 条件 | 需求依据 |
|---|---|---|---|---|
| 空闲 | 开台 | 占用 | 输入用餐人数（1~99） | TABLE-02 |
| 占用 | 结账完成 | 待清台 | 收款完成 | PAY-04① |
| 待清台 | 清台 | 空闲 | 服务员手动操作 | TABLE-04 |
| 待清台 | 反结账 | 占用 | 仅店长角色 | ORDER-04 |

### 2.2 订单状态机

```
开台 ──▶ 已开台 ──下单──▶ 已下单 ──结账完成──▶ 已结账
             │  0元结账       ▲                  │
             └────────────────┴────反结账────────┘
```

| 当前状态 | 操作 | 目标状态 | 条件 | 需求依据 |
|---|---|---|---|---|
| — | 开台 | 已开台 | 开台时自动创建，金额为 0 | ORDER-01 |
| 已开台 | 下单 | 已下单 | 购物车提交成功 | POS-04③ |
| 已下单 | 加菜下单 | 已下单 | 新明细追加，状态不变 | ORDER-02 |
| 已开台 | 0 元结账 | 已结账 | 无明细订单，不产生支付记录 | PAY-04③ |
| 已下单 | 结账完成 | 已结账 | 已收总额 = 应收金额 | PAY-04① |
| 已结账 | 反结账 | 已下单（0 元无明细订单回"已开台"） | 仅店长；桌台处于待清台 | ORDER-04④⑤ |

> 说明：订单状态只表示订单生命周期；明细的"已退"（2.3）不影响订单状态，仅触发订单金额重算（ORDER-03②）。订单无"已退/退款"状态，结账后的纠错通过反结账（ORDER-04）完成。

### 2.3 订单明细状态机

```
下单 ──▶ 待制作 ──出餐──▶ 已出餐
          │
          └──退菜──▶ 已退
```

| 当前状态 | 操作 | 目标状态 | 条件 | 需求依据 |
|---|---|---|---|---|
| — | 下单 | 待制作 | 购物车提交，进入厨房 | POS-04② |
| 待制作 | 出餐 | 已出餐 | 后厨操作 | KDS-02 |
| 待制作 | 退菜 | 已退 | 订单未结账；必须填写原因；已出餐明细不可退 | ORDER-03 |

## 3. 核心流程

### 3.1 总览：一条主线，三个角色

```
顾客到店
   │
   ▼  【服务员】
桌台看板 ──▶ 开台(人数) ──▶ 点餐页(购物车) ──▶ 下单
   ▲                                                  │
   │                                                  ▼
   │                                            【后厨】
   │                                      KDS 待制作 ──▶ 出餐
   │                                                  │
   └────────────── 用餐中循环：加菜 / 退菜 ◀──────────┘
   │
   ▼  【服务员】
结账 ──▶ 桌台待清台 ──▶ 清台 ──▶ 空闲
   ▼
【店长】反结账（纠错，仅待清台期间可反）
```

### 3.2 服务员流程

**开台**（TABLE-01、TABLE-02）：

1. 在桌台看板选择一张空闲桌台
2. 输入用餐人数（1~99 的整数）
3. 开台成功：桌台变为"占用"，系统自动创建订单（状态"已开台"，金额 0），进入点餐页

**点餐下单**（POS-01 ~ POS-04）：

1. 点餐页按分类浏览菜品，加入购物车，可填写口味备注
2. 沽清菜品标记售罄，不可加入购物车
3. 提交下单：购物车清空，明细进入 KDS（待制作），订单变为"已下单"

**加菜 / 退菜**（ORDER-02、ORDER-03）：

- 加菜：从桌台看板点击占用中的桌台，重新进入点餐页，再次下单即追加到原订单
- 退菜：仅未结账订单可退；仅"待制作"明细可退；必须填写原因；退菜后订单金额自动重算

**结账**：见 3.4。

**清台**（TABLE-04）：

1. 结账完成后桌台为"待清台"
2. 服务员清理完毕后执行清台，桌台恢复"空闲"，可再次开台

### 3.3 后厨流程（KDS-01 ~ KDS-03）

1. KDS 待制作区自动显示新明细：菜名、数量、备注、桌台号、下单时间
2. 出餐：将明细标记为"已出餐"，移出待制作区
3. 沽清：菜品售罄时标记沽清，点餐端立即不可选；恢复上架同理

### 3.4 结账流程（PAY-01 ~ PAY-04）

1. 从桌台看板选择占用中的桌台，发起结账
2. 结账页确认消费明细；可输入优惠金额（不超过原价总额）；可抹零（舍去角分）
3. 收款：选择支付方式、输入金额，可分多次收款（组合支付），每次记录方式、金额、时间、操作人
4. 已收总额等于应收金额时完成结账：订单变为"已结账"，桌台变为"待清台"

特殊情况：

- **0 元订单**：已开台未点单的订单直接完成结账，不产生支付记录（PAY-04③）
- **取消结账**：结账过程中取消，本次已收款项作废退回，订单保持未结、桌台保持占用（见 4.2）

### 3.5 反结账流程（店长，ORDER-04）

1. 条件检查：订单已结账，且桌台仍为"待清台"（已清台的订单不可反结账）
2. 执行反结账：订单恢复"已下单"（未结；0 元无明细订单恢复"已开台"），原支付记录标记为失效（不删除），优惠金额清零、应收金额重算为原价总额，桌台恢复"占用"
3. 之后可修改订单（加菜/退菜）后重新走结账流程

## 4. 异常与边界场景

| 编号 | 场景 | 系统行为 | 需求依据 |
|---|---|---|---|
| 4.1 | 开台后未点单顾客离开 | 0 元订单直接结账，不产生支付记录，桌台进入待清台 | PAY-04③ |
| 4.2 | 结账中途取消 | 本次已收款项作废退回，订单保持未结、桌台保持占用，可再次发起结账 | —（本文补充定义） |
| 4.3 | 退已出餐的菜 | 不允许，仅"待制作"明细可退 | ORDER-03 |
| 4.4 | 购物车菜品被沽清 | 下单时系统拒绝并提示，需移除该菜品后重新下单 | POS-03② |
| 4.5 | 停用用户登录 | 拒绝登录 | AUTH-04② |
| 4.6 | 登录超时 | 超过 4 小时需重新登录 | AUTH-01③ |
| 4.7 | 删除基础数据 | 存在菜品的分类、存在桌台的区域、占用/待清台的桌台均不可删除，系统给出提示 | BASE-01②、BASE-03②、BASE-04② |
| 4.8 | 无权限访问模块 | 进入模块时被系统拒绝并提示无权限 | AUTH-03②③ |
