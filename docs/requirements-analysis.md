# RestoFlow 需求规格说明书

## 1. 文档说明

- **目的**：本文档是 V1 功能范围与验收标准的权威定义，是开发、测试与验收的统一依据
- **范围约定**：本文档只描述系统行为与结果，不包含实现技术选型（归 system-design.md）与操作步骤细节（归 business-process.md）
- **维护规则**：任何需求变更须评审通过，同步更新本文档并在 CHANGELOG.md 记录，之后方可进入编码

## 2. 需求总览

## 3. 功能需求详述

### 3.1 登录与权限（AUTH）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| AUTH-01 | 用户登录：输入用户名和密码登录系统，成功后进入首页并保持登录状态 | ①用户名或密码错误时提示"用户名或密码错误"且不进入系统；②登录状态保持 4 小时，期间刷新页面无需重新登录；③登录状态超时后需重新登录 |
| AUTH-02 | 登出：用户主动登出，当前客户端登录状态立即失效 | 登出后使用该客户端再次访问任何功能，要求重新登录 |
| AUTH-03 | 访问控制：系统按角色控制业务模块的访问；首页固定展示全部业务模块，进入模块时进行权限校验 | ①用户登录后可以访问系统首页；②用户进入业务模块时，系统校验角色是否拥有该模块访问权限；③无权限用户无法访问对应业务模块 |
| AUTH-04 | 用户管理：管理员维护用户（新增、修改、停用） | ①管理员可创建用户并分配角色；②被停用的用户无法登录；③非管理员账号进入该功能时被系统拒绝 |

角色与模块权限矩阵（固定配置）：

| 模块 | 服务员 | 后厨 | 店长 | 管理员 |
|---|---|---|---|---|
| 桌台（含开台、点餐） | ✓ | | ✓ | ✓ |
| 订单（含结账） | ✓ | | ✓ | ✓ |
| 厨房 KDS | | ✓ | ✓ | ✓ |
| 基础数据 | | | ✓ | ✓ |
| 用户管理 | | | | ✓ |

> 反结账为订单模块内的例外：仅店长角色可执行（ORDER-04④）。

### 3.2 桌台管理（TABLE）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| TABLE-01 | 桌台看板：按区域分组展示所有桌台及状态（空闲/占用/待清台） | ①看板按区域分组显示全部桌台及当前状态；②其他终端引起桌台状态变化后，看板自动更新，无需手动刷新页面 |
| TABLE-02 | 开台：选择空闲桌台并输入用餐人数，开台后进入该桌台的点餐页 | ①仅空闲状态的桌台可开台；②用餐人数为必填项，取值 1~99 的整数；③开台成功后桌台状态变为"占用" |
| TABLE-03 | 进入点餐页：点击占用中的桌台，进入该桌台的点餐页继续点餐 | ①占用中的桌台可进入点餐页，查看已点菜品并继续加菜；②空闲、待清台状态的桌台不可进入点餐页 |
| TABLE-04 | 清台：待清台桌台由服务员清理后手动清台 | ①仅待清台状态的桌台可执行清台；②清台后桌台恢复"空闲"，可再次开台 |

### 3.3 点餐（POS）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| POS-01 | 菜品选择：点餐页按分类展示菜品，菜品可加入购物车、调整数量、移除 | ①菜品按分类分组展示；②选中菜品加入购物车，数量可增减、可移除；③购物车实时显示菜品清单与金额合计 |
| POS-02 | 口味备注：下单前可为每道菜填写备注 | ①每道菜可填写一条备注（如"不要辣""少盐"）；②备注随明细传递到 KDS 展示；③备注为选填项 |
| POS-03 | 沽清拦截：已沽清的菜品不可点 | ①已沽清菜品在点餐页标记为售罄，不可加入购物车；②下单时系统再次校验，含沽清菜品的下单被拒绝并提示 |
| POS-04 | 下单：购物车中的菜品批量下单，进入厨房制作流程 | ①下单成功后购物车清空；②新增明细以"待制作"状态出现在 KDS；③订单状态变为"已下单" |

### 3.4 订单（ORDER）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| ORDER-01 | 开台建单：开台时自动创建订单 | ①每次开台自动创建一张与该桌台绑定的订单；②订单初始状态为"已开台"，金额为 0 |
| ORDER-02 | 加菜：同一订单可多次下单加菜 | ①用餐过程中再次下单，新明细追加到当前订单；②新明细与首次下单同样进入厨房制作流程 |
| ORDER-03 | 退菜：未结账的订单可退菜 | ①退菜必须填写原因；②退菜后明细标记为"已退"，订单金额自动重算；③已结账订单不允许退菜，需先反结账 |
| ORDER-04 | 反结账：已结账的订单可撤销结账 | ①反结账后订单恢复未结状态，可修改后重新结账；②反结账后桌台恢复"占用"；③原支付记录保留并标记为失效，不删除；④反结账仅店长角色可执行；⑤仅桌台处于待清台状态的订单可反结账，已清台的订单不可反结账 |
| ORDER-05 | 订单查询：查看全部订单及详情 | ①订单列表可按日期、状态筛选；②订单详情展示消费明细、金额构成、支付记录、操作记录 |

### 3.5 厨房 KDS（KDS）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| KDS-01 | 制作单展示：KDS 展示待制作与已出餐的明细 | ①下单后新明细自动出现在 KDS 待制作区，无需手动刷新；②每条明细展示菜名、数量、备注、桌台号、下单时间 |
| KDS-02 | 出餐操作：后厨将明细标记为已出餐 | ①后厨可将明细从"待制作"标记为"已出餐"；②已出餐明细移出待制作区 |
| KDS-03 | 沽清管理：后厨在 KDS 页面设置菜品沽清 | ①后厨可将菜品标记为沽清或恢复在售；②沽清状态在点餐端立即生效 |

### 3.6 结账（PAY）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| PAY-01 | 结账：对未结账订单发起结账，展示消费明细与金额 | ①占用中桌台可发起结账；②结账页展示消费明细、原价总额、优惠金额、应收金额 |
| PAY-02 | 优惠与抹零：结账时输入优惠金额，可抹零 | ①优惠金额输入后应收金额实时重算；②优惠金额不能超过原价总额；③抹零后应收金额舍去角分 |
| PAY-03 | 组合支付：同一订单可用多种支付方式分多次收款 | ①每次收款记录支付方式、金额、时间、操作人；②已收总额等于应收金额时方可完成结账；③已收总额不能超过应收金额 |
| PAY-04 | 结账完成：结账完成后订单关闭，桌台进入待清台 | ①结账完成后订单状态变为"已结账"，桌台状态变为"待清台"；②未收齐应收金额时系统不允许完成结账；③原价总额为 0 的订单（已开台未点单）可直接完成结账，不产生支付记录 |

### 3.7 基础数据维护（BASE）

| 编号 | 需求描述 | 验收标准 |
|---|---|---|
| BASE-01 | 菜品分类维护：新增、修改、删除菜品分类 | ①可新增、修改、删除分类；②存在菜品的分类不可删除，系统给出提示 |
| BASE-02 | 菜品维护：新增、修改、删除菜品 | ①可维护菜品名称、价格、所属分类；②菜品价格精确到分；③菜品删除或改价后，历史订单仍显示下单时的菜名与价格 |
| BASE-03 | 桌台区域维护：新增、修改、删除桌台区域 | ①可新增、修改、删除区域；②存在桌台的区域不可删除，系统给出提示 |
| BASE-04 | 桌台维护：新增、修改、删除桌台 | ①可维护桌台名称、座位数、所属区域；②占用或待清台状态的桌台不可删除；③桌台变更在看板立即生效 |
| BASE-05 | 支付方式：系统预置现金、微信、支付宝三种支付方式 | ①结账时只能从预置支付方式中选择；②V1 不提供支付方式维护页面 |

## 4. 非功能需求

| 编号 | 要求 | 说明 |
|---|---|---|
| NF-01 | 金额精确 | 所有金额精确到分，计算过程不得出现精度误差 |
| NF-02 | 状态一致性 | 桌台、订单、明细的状态流转符合业务规则；结账等关键操作涉及的状态更新要么全部生效、要么全部不生效 |
| NF-03 | 操作留痕 | 开台、下单、退菜、结账、反结账、清台等业务操作均记录操作人与操作时间 |
| NF-04 | 数据实时性 | 桌台看板与 KDS 的数据变化后 5 秒内自动更新，无需手动刷新 |
| NF-05 | 密码安全 | 用户密码不得以明文形式存储 |
